この説明書は、測定用ツール(Phase 0 の Probe)の物です。アプリ本体の物ではありません。
{{ app.name }} のアプリ本体は、まだありません。端末のカメラの映像を PC に生で映すことは、まだできません。 このツールでできるのは、端末で 5 秒だけ撮ってファイルに保存し、そのファイルを PC で復号して数えたり、ウィンドウで繰り返し再生したりすることだけです。
この説明書の画面や出力の例に出るファイル名・日時は、説明のための架空の物です。数字は、dtab d-01J(Android 7.0)で実際に測った値を使っています。

1. はじめに(このツールでできること・できないこと)

{{ app.name }} は、Android 端末のカメラの映像を、Windows PC の 1 枚のウィンドウに映すためのソフトとして作っている物です。通話や画面共有で、手元(楽器の指、紙に書いた図、ボードゲームの盤面など)を見せるために、机の上の端末をカメラとして使います。PC 側は普通のウィンドウに映すだけで、Discord の画面共有や録画のソフトでは、そのウィンドウを選んで使う形にします。

本体を作る前に、「この端末でカメラの映像を圧縮できるか」「PC で復号してウィンドウに出せるか」「そのウィンドウを画面共有で取り込めるか」を確かめる必要があります。そのための道具が、この測定用ツール(Probe)です。

できること

  • 端末のカメラと、H.264 のエンコーダー(映像を圧縮する部品)の一覧を画面に出す
  • 端末のカメラで 5 秒だけ撮って H.264 に圧縮し、端末の中にファイルとして保存する
  • そのファイルを PC で復号し、フレームの数と、絵が出るまでの溜め(遅れ)を数える(decode)
  • そのファイルを PC のウィンドウで繰り返し再生する(show)。画面共有で選んで、黒くならないかを見るため

できないこと

  • 端末のカメラの映像を、いま撮っているまま PC に映すこと(本体でこれから作ります)
  • 端末と PC をネットワークでつなぐこと(Probe は通信しません。ファイルは USB の adb で写します)
  • 音を撮ること、長く録画すること
  • 仮想カメラとして、ほかのソフトのカメラの一覧に出ること(本体でも作りません)

2 つの部品

部品動く所やること
Android の Probe(アプリ名「CamPane Probe」)Android 端末一覧を出す。5 秒撮って保存する
PC の Probe(CamPane.Probe.exe)Windows PCデコーダーの一覧、ファイルの復号と数え、ウィンドウでの再生

3. 入れ方

3.1 PC の Probe

  1. {{ release.zip }} を右クリックし、「すべて展開」で好きな場所に展開します。
  2. 展開した中に CamPane-Probe-v{{ app.version }}-win-x64 のフォルダが 1 つあります。その中に CamPane.Probe.exe があります。
  3. そのフォルダを開き、エクスプローラーのアドレス欄に powershell と打って Enter を押します。そのフォルダで PowerShell が開きます(管理者でなくてかまいません)。
  4. 次を打って Enter を押します。使い方の説明が出れば、入れ終わりです。 
    .\CamPane.Probe.exe

exe をダブルクリックしても、黒い窓が一瞬出て閉じるだけです。PowerShell から動かしてください。

この説明書の命令の中の「¥」は、バックスラッシュ(フォルダの区切りの記号)です。日本語のキーボードでは ¥ キーで打てます。

3.2 adb

  1. Google の Android Developers のサイトから「SDK Platform-Tools」の Windows 版をダウンロードし、展開します。中に adb.exe があります。
  2. 端末で「開発者向けオプション」を出します。多くの機種では、設定の「端末情報」(「タブレット情報」)の「ビルド番号」を 7 回続けて押すと出ます。
  3. 「開発者向けオプション」の「USB デバッグ」をオンにします。
  4. 端末と PC を USB ケーブルでつなぎます。端末に「USB デバッグを許可しますか?」と出たら、「許可」を押します。
  5. PC の PowerShell で、adb.exe のあるフォルダから次を打ちます。端末の番号の後ろに device と出れば、つながっています。 
    .\adb.exe devices
この説明書では、PowerShell を 2 つの場所で使います。adb の命令は、いつも adb.exe のあるフォルダの PowerShell で .\adb.exe と打ちます。Probe の命令は、CamPane.Probe.exe のあるフォルダの PowerShell で .\CamPane.Probe.exe と打ちます。2 つの PowerShell を開いたままにしておくと楽です。

3.3 Android の Probe

次のどちらかで入れます。

A. adb で入れる(おすすめ)

  1. APK を、adb.exe と同じフォルダに置きます。
  2. 次を打ちます。Success と出れば入れ終わりです。 
    .\adb.exe install {{ release.apk }}

B. 端末だけで入れる

  1. APK を端末に写し、端末のファイルの一覧から開きます。
  2. 「提供元不明のアプリ」を許可するよう求められたら、許可します。場所は Android の版と機種で違います(Android 7 では多くの機種で、設定の「セキュリティ」の中にあります)。
  3. 「インストール」を押します。入れ終えたら、提供元不明のアプリの許可は元に戻してかまいません。

4. 使い方

一続きの流れは次の 5 つです。順に進めてください。

順やること使う物
4.1端末で 5 秒撮るAndroid の Probe
4.2撮ったファイルを PC へ写すadb
4.3decode でフレームと溜めを数えるPC の Probe
4.4show でウィンドウに映し、Discord の画面共有で選んで、黒くないか見るPC の Probe と Discord
4.5映像のファイルを消すadb と PC

4.1 端末で 5 秒撮る

  1. 端末を机に置き、カメラ(背面)を映してよい物に向けます。部屋や人、画面、書類が映らないようにしてください。
  2. アプリ「CamPane Probe」を開きます。端末、カメラ、エンコーダーの一覧が出て、最後に --- 終わり --- と出ます(図 1)。
  3. 画面のいちばん上の「5 秒圧縮して保存」を押します(一覧を下へ送っていたら、上へ戻すと見えます)。
  4. 初めてのときは、カメラの権限を求められます。「許可」を押すと、続けて撮り始めます。
  5. 撮っている 5 秒ほどの間は、アプリを開いたままにします。裏に回したり画面を消したりすると、そこで止まり、途中のファイルは消えます。
  6. 画面の最後に 結果: 成功(1280x720・30 fps) と 保存したパス: の行が出れば、撮れています。保存したパスを控えておきます。

撮れたときに画面に出る行の例です(ファイル名は架空の例。行は一部を略した)。

結果: 成功(1280x720・30 fps)
出たフレームの数: 149
キーフレームの数: 5
合計のバイト数: 152804
SPS のプロファイル: profile_idc=66(Constrained Baseline) level_idc=51(5.1)
保存したパス: /storage/emulated/0/Android/data/io.github.takosasidev.campane.probe/files/campane_probe_20260101_120000.h264
adb からも撮れます。先に 4.1 の手順で 1 回撮って、カメラの権限を許可しておいてください。adb.exe のあるフォルダで打ちます。 
.\adb.exe shell am start -n io.github.takosasidev.campane.probe/.MainActivity --es action encode
encode は GL 経由(ボタンと同じ)、encode-direct は直接の経路です。直接の経路は比べるための物で、端末によってはフレームが 1 枚も出ません。

4.2 撮ったファイルを PC へ写す

  1. 端末と PC を USB でつなぎ、adb.exe のあるフォルダの PowerShell で .\adb.exe devices と打って、device と出ることを確かめます。
  2. 同じ PowerShell で、4.1 で控えた「保存したパス」を使って次を打ちます(下は架空の例。日時の所を、自分の保存したパスに合わせます)。 
    .\adb.exe pull /storage/emulated/0/Android/data/io.github.takosasidev.campane.probe/files/campane_probe_20260101_120000.h264
  3. 1 file pulled と出れば、adb.exe のあるフォルダに .h264 のファイルができています。
  4. そのファイルを、エクスプローラーで CamPane.Probe.exe のあるフォルダへ移します。

USB のファイル転送(エクスプローラー)で取り出せるかは、作者は確かめていません。adb を使ってください。

4.3 decode で数える

  1. CamPane.Probe.exe のあるフォルダの PowerShell で、次を打ちます(ファイル名は自分の物に)。 
    .\CamPane.Probe.exe decode campane_probe_20260101_120000.h264
  2. 数秒で、(a)〜(d) の 4 回の復号の記録と、最後に「比べ」の行が出ます。ウィンドウは出ません。
  3. 失敗: で始まる行が無いことを確かめます。この Probe は、失敗しても終了の値を変えません。失敗は必ず 失敗: の行で知らせます。
  4. 「比べ」の行の読み方は、5 章を見てください。

4.4 show で窓に映し、Discord の画面共有で選ぶ

  1. Discord を開き、自分だけのサーバーのボイスチャンネルなど、見られても困らない所に入ります。
  2. PC の Probe のフォルダの PowerShell で、次を打ちます。 
    .\CamPane.Probe.exe show campane_probe_20260101_120000.h264
  3. 題名が「CamPane Probe」のウィンドウが開き、5 秒の映像が繰り返し流れます。ウィンドウの大きさは変えられ、絵は縦横の比を保って広がります。
  4. Discord で画面共有を始め、共有する物を選ぶ所で、ウィンドウ(アプリ)の一覧から「CamPane Probe」を選びます。
  5. 共有のプレビューで、映像が見えるか、黒いかを見ます。録画のソフトでも、同じようにこのウィンドウを選んで見ます。
  6. 結果(見えた / 黒かった、使ったソフトの名前)を書き留めます。
  7. 画面共有を止め、「CamPane Probe」のウィンドウを閉じます。閉じなくても、10 分たつと自分で閉じます。
取り込みで黒くならないかは、作者の環境でもまだ確かめていません。本体の作りを決めるための大事な確認なので、結果は見えた・黒かったのどちらでも役に立ちます。

ウィンドウを閉じると、PowerShell に次の形の行が出ます(形の例。数は架空)。

show: ウィンドウが閉じられた
  出せたフレーム: 447 枚(4 周目、15.2 秒)  絵の大きさ: 1280x720(...)

4.5 映像のファイルを消す

映像には部屋が映っています。確かめ終えたら、端末と PC の両方からファイルを消してください。
  1. 端末のファイルを消します。adb.exe のあるフォルダの PowerShell で打ちます(保存したパスは自分の物に)。 
    .\adb.exe shell rm /storage/emulated/0/Android/data/io.github.takosasidev.campane.probe/files/campane_probe_20260101_120000.h264
  2. 保存先にほかのファイルが残っていないか確かめます。何も出なければ空です。 
    .\adb.exe shell ls /storage/emulated/0/Android/data/io.github.takosasidev.campane.probe/files/
  3. PC のファイルを消します。CamPane.Probe.exe のあるフォルダの PowerShell で打ちます。 
    Remove-Item .\campane_probe_20260101_120000.h264
  4. ごみ箱を経由しないので、これで PC からも消えています。エクスプローラーで消したときは、ごみ箱も空にします。adb.exe のあるフォルダに写しの残りが無いかも見ます。

5.2 decode の「比べ」

decode は、同じファイルを入れ方を変えて 4 回復号し、最後に 1 行ずつ並べます。

行入れ方見る所
(a)そのまま、NAL(映像の小さな塊)を 1 つずつ入れる基準
(b)デコーダーを低遅延の設定にして入れる(a) より溜めが減るか
(c)(b) に加えて、1 枚の絵の塊を 1 回にまとめて入れる入れ方で溜めが変わるか
(d)(c) に加えて、映像の頭の設定(SPS)に「並べ替えなし」(max_num_reorder_frames=0)を書き足して入れる溜めが 0〜1 枚になるか

各行の「遅れ」の、「絵に直すと 中央値 ○・最大 ○ 枚」が、デコーダーが絵を出すまでに溜めた枚数です。30 fps なら 1 枚は約 33 ミリ秒なので、溜めが 30 枚なら約 1 秒遅れて映ることになります。0〜1 枚なら、溜めはありません。

dtab d-01J で撮ったファイルでの結果です(出力の例。ファイル名は架空、行は略した)。

比べ(...):
  (a) 今のまま:         ... 絵に直すと 中央値 32・最大 35 枚(120 枚で) / 復号 149 枚 ...
  (b) 低遅延:           ... 絵に直すと 中央値 17・最大 17 枚(132 枚で) / 復号 149 枚 ...
  (c) 低遅延+1 枚ずつ:  ... 絵に直すと 中央値 17・最大 17 枚(132 枚で) / 復号 149 枚 ...
  (d) (c)+SPS 書き足し: ... 絵に直すと 中央値 1・最大 1 枚(148 枚で) / 復号 149 枚 ...
  デコーダーは (a)〜(d) とも同じ: Microsoft H264 Video Decoder MFT {...}

読み方の例:

  • dtab d-01J のエンコーダーの映像は、SPS に並べ替えの情報(VUI)がありません。Microsoft のデコーダーは、並べ替えがあっても困らないよう、約 35 枚を溜めてから出しました((a))。
  • 低遅延の設定では、溜めは 17 枚に減りました((b))。まとめて入れても変わりませんでした((c))。
  • SPS に「並べ替えなし」を書き足すと、1 枚になりました((d))。残る 1 枚は、次の塊を入れてから出力を取る、測り方の分です。
  • 「復号 149 枚」が 4 行とも同じなら、どの入れ方でも絵は全部出ています。
  • 最後の行が「デコーダーが違う(比べにならない)」のときは、4 回の比べは当てになりません。

ほかの端末で撮ったファイルでは、数が違うことがあります。

6. 困ったとき

6.1 Android の Probe

出た言葉・様子わけと、すること
直接の経路ではフレームが来ない(2 秒で 0 枚)カメラがエンコーダーへ直接は絵を渡せない端末です(dtab d-01J もそうでした)。ボタン、または --es action encode の GL 経由で撮ってください
フレームが 1 枚も出なかったGL 経由でも出ないときは、その端末では撮れません。画面の行を全部控えて、Issues で知らせてください
1280x720 でできなかった: …1280x720 で撮れなかったので、640x480 で 1 回やり直しています。撮れなかった理由は、この行のコロンの後に出ます。続きの行も見てください

カメラを開けなかった: onError …(ほかで使用中)ほかのアプリがカメラを使っています。そのアプリを閉じてから撮ってください

7. 安全とプライバシー

  • 映像には部屋が映ります。撮る前に、映ってよい物にカメラを向けてください。確かめ終えたら、端末と PC の両方からファイルを消してください(4.5)。
  • Android の Probe が求める権限はカメラだけです。インターネットの権限は無く、通信しません。マイクも使いません。
  • カメラを使うのは、ボタンを押してからの 5 秒ほどだけです。アプリが裏に回ったり画面が消えたりすると、すぐにカメラを閉じます。
  • PC の Probe も通信しません。復号した絵をファイルに保存しません。
  • 撮ったファイルは、端末の中ではこのアプリ用のフォルダに置かれ、アプリを消すと一緒に消えます。
  • このツールの出力を Issues などに貼るときは、ファイルの中身(映像)は貼らず、文字の行だけにしてください。

8. 片付け

測り終えて、もう使わないときの手順です。

  1. 4.5 の手順で、端末と PC の映像のファイルを消します。
  2. 端末のアプリ「CamPane Probe」を消します。端末でアプリのアイコンを長押しして消すか、adb.exe のあるフォルダの PowerShell で次を打ちます。アプリを消すと、端末に残ったファイルも一緒に消えます。 
    .\adb.exe uninstall io.github.takosasidev.campane.probe
  3. PC の Probe は、展開したフォルダごと消します。Windows に何かを登録していないので、ほかに消す物はありません。
  4. USB デバッグは、使わないならオフにします(「開発者向けオプション」の「USB デバッグ」)。
  5. 端末だけで APK を入れたときは、提供元不明のアプリの許可が元に戻っているか確かめます。
